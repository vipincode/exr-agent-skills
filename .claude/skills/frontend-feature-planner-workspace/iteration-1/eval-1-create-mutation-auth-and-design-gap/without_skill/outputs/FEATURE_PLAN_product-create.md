# FEATURE PLAN — Admin-only "Create Product" form (frontend → backend binding)

Status: PLAN ONLY. No binding/component code is written here.
Scope: wire a new admin-only create-product form in the `products` feature to the existing
backend `POST /api/products` endpoint. Frontend stack: Next.js App Router + TS + Tailwind v4 +
shadcn/ui + axios + Zod 4 + TanStack Query v5 + RHF 7.

---

## 1. Ground truth — the REAL backend contract

Read directly from `backend/src/modules/products/*` (not guessed).

### Endpoint
`POST /api/products` — `backend/src/modules/products/products.routes.ts`
```
productsRouter.post("/", protect, requireRole("admin"), validate({ body: createProductBody }), ctrl.create);
```
- **Auth: required.** `protect` (valid Bearer access token) THEN `requireRole("admin")`.
  A non-admin gets `401` (UnauthorizedError) — gating is enforced server-side, not just UI.
- Validation: Zod `createProductBody` on the request body (422 on failure).

### Request body — `createProductBody` (products.schema.ts)
| Field | Type / rule | Required | Default | Notes |
|---|---|---|---|---|
| `name` | `string().min(1)` | yes | — | slug is derived server-side from this; do NOT send slug |
| `price` | `number().int().positive()` | yes | — | **in CENTS** (integer). 2400 = $24.00 |
| `currency` | `string().length(3)` | no | `"USD"` | ISO 4217 |
| `category` | `string().min(1)` | yes | — | |
| `inStock` | `boolean()` | no | `true` | |
| `imageUrl` | `url()` | no | — | must be a valid URL if present |

`slug` is generated by the service (`name.toLowerCase().replace(/\s+/g,"-")`) and `slug` is
`unique` in Mongo — so a duplicate name → **409 ConflictError**. The form must surface this.

### Success response — 201 `created()` envelope (app-response.ts)
```json
{ "success": true, "data": <ProductDTO>, "message": "Product created" }
```
`ProductDTO` (products.service.ts): `{ id, name, slug, price, currency, category, inStock, imageUrl? }`.

### Error response envelope (ARCHITECTURE.md)
```json
{ "success": false, "message": "<string>", "code": "<string>" }
```
Statuses to handle: `422` ValidationError (bad/missing fields), `401` UnauthorizedError
(not logged in / not admin), `409` ConflictError (duplicate slug from duplicate name).

### Transport
- Browser calls **same-origin** `/api/products`. The catch-all BFF proxy
  `frontend/src/app/api/[...path]/route.ts` already forwards `/api/*` to `BACKEND_URL`.
  **No new BFF route is needed.**
- Use the shared axios instance `frontend/src/lib/axios.ts` (`baseURL: "/api"`), so call `api.post("/products", body)`.

## 2. Current frontend state & GAPS

From `frontend/MODULE_REGISTRY.md` and the source:

- `features/products` is **DESIGN ONLY** — it owns `components/product-card.tsx` and
  `template/products-grid.tsx`, with **no** `api/ hooks/ types/ schema/`. The grid renders
  hardcoded `SAMPLE` data.
- **There is NO create-form component** — it must be built (design gap). This plan stops at
  the binding design; building the form UI is a `figma-to-component` / `html-to-component` job,
  but the field choices below tell that builder exactly what to render.
- Shared form fields available (`components/shared/form/`): `InputField`, `SelectField`,
  `TextareaField`, `CheckboxField`. **No NumberField exists** — relevant for `price`.
- `useAuth()` (`hooks/use-auth.ts`) currently returns `{ user: null }`. It is the role accessor
  but is a stub — admin gating in the UI depends on it actually resolving a user/role.

### Design ↔ contract mismatches to resolve
1. **price units.** Card/grid display price as a formatted string (`"$24.00"`). Backend wants an
   **integer cents** number. The form must collect a human dollar amount and convert
   dollars → cents (`Math.round(dollars * 100)`) before POST. Recommend a `priceDollars` input
   in the form schema, transformed to `price` (cents) at submit. Validate it is > 0.
2. **No NumberField.** Either (a) use `InputField` with `type="number"` + Zod `coerce.number`,
   or (b) add a shared `NumberField` to `components/shared/form` (registry update). Recommend (a)
   to stay within existing shared fields; revisit if numbers recur.
3. **currency / category** are free strings on the backend. For a clean admin UX, render
   `currency` as a `SelectField` (USD default) and `category` as `SelectField` if a known list
   exists, else `InputField`. Backend accepts any 3-char currency / any non-empty category.
4. **slug** must NOT be a form field (server-derived). Duplicate name = 409; show that error on
   the `name` field or as a form-level toast.

## 4. Admin-only gating (defense in depth)

- **UI gate:** `product-create-form` (and any "New product" button) renders only when
  `useAuth().user?.role === "admin"`. Non-admins never see the form. Note `useAuth` is currently
  a stub returning `null`; it must resolve a real user/role for the gate to function — flag as a
  prerequisite/dependency.
- **Server gate (authoritative):** backend already enforces `protect` + `requireRole("admin")`,
  returning `401` otherwise. The UI gate is UX only; never rely on it for security.
- **Token:** requests must carry the access token the backend `protect` expects (Bearer). Confirm
  how the app currently attaches auth to `api`/BFF (axios interceptor or proxy-forwarded cookie).
  This is the one open dependency — see §5.

## 5. Open questions / dependencies (must confirm before building)

1. **Auth token transport.** How does an authenticated request currently reach the backend —
   does the BFF proxy forward a session cookie, or does axios attach a Bearer token? `useAuth` is
   a stub, so the real auth wiring needs confirming before the mutation can succeed.
2. **price input UX.** Confirm dollars-in-form → cents-on-submit (recommended) vs. raw cents entry.
3. **category / currency option lists.** Are there fixed allowed values (→ SelectField), or free text?
4. **NumberField.** Acceptable to use `InputField type="number"`, or add a shared `NumberField`?
5. **Where the form mounts.** New `/products/new` route/page, a modal on the products grid, or
   inline — affects the template wiring (not the binding).

## 6. Conclusion

The backend `POST /api/products` is admin-gated, validated, and returns the standard
`{success,data,message}` envelope; the BFF proxy + shared axios mean **no new transport plumbing**.
The real work is net-new on the frontend: a `products` binding layer (types/schema/api/hook) plus a
**brand-new admin-gated create-form component** that did not exist, with two contract gaps to bridge —
**price dollars↔cents** and **UI admin gating on a currently-stubbed `useAuth`**. Duplicate-name → 409
and 401/422 errors must be surfaced on the form. After binding, invalidate `["products"]` to refresh the grid.
