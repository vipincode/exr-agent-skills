## Stack

- **Express 4** (`^4.18.2`) — Express 4 does **not** forward async rejections to the
  error middleware. Every async handler **must** be wrapped in `catchAsync`
  (`src/utils/catchAsync.ts`). This is required, not optional.
- **TypeScript 5.1**, **CommonJS** (`"module": "commonjs"`, `"moduleResolution": "node"`),
  `"strict": false`. No `"type": "module"` in `package.json`.
- **Mongoose 7** (`^7.4.0`) for data. Models are untyped (`mongoose.model(...)` with no
  generic/interface) — schemas define the shape.
- **jsonwebtoken 9** (`^9.0.0`) for tokens — **not** JOSE. Verification happens inline in
  `src/middleware/auth.ts`; there is no shared sign/verify helper module yet.
- **bcryptjs** is installed but **not yet used anywhere** (no hashing code exists).
- **Joi 17** (`^17.9.2`) for validation, via `validateBody` (`src/middleware/validate.ts`).
  **Not Zod.**
- **morgan** (`"dev"` format) for HTTP request logging; application logging is `console.*`.
  No pino/winston.
- **cors** with `origin: process.env.CORS_ORIGIN`.
- **Test:** jest 29 + supertest 6 (devDependencies). **No test files or jest config exist yet.**
- **Package manager:** npm (no lockfile committed in the scanned tree; `npm` assumed from
  the plain `package.json`).

## Paradigm — layered (type-grouped), not domain-module

Files are grouped **by role**, not by domain. A resource's pieces are spread across
sibling top-level folders:

```
src/
  controllers/   <name>.controller.ts   — HTTP layer, wrapped in catchAsync
  services/      <name>.service.ts      — business logic + data access
  routes/        <name>.routes.ts       — Router, default-exported, mounted in index.ts
  models/        <Name>.ts              — Mongoose schema + model (PascalCase filename)
  middleware/    auth.ts, errorHandler.ts, validate.ts
  utils/         ApiError.ts, catchAsync.ts, formatDate.ts
  index.ts       app construction + mongoose.connect + listen (all in one file)
```

**New modules follow this layered shape** — a new `orders` feature adds
`controllers/order.controller.ts`, `services/order.service.ts`, `routes/order.routes.ts`,
`models/Order.ts`, and mounts the router in `src/index.ts`. Do **not** introduce
`src/modules/<name>/` folders here; that would conflict with everything around it.

Cross-module needs go through the other resource's **service** (`product.service.ts`),
never its model — `product.controller.ts` already follows this
(`import * as productService from "../services/product.service"`).

## Import convention

Relative imports with **no file extension** — `import { catchAsync } from "../utils/catchAsync";`.
This is CommonJS + `moduleResolution: node`, so `.js` extensions are **not** used and must
not be added. There are **no path aliases** (`compilerOptions.paths` is unset); use
relative paths.

## Project layout

`rootDir: src`, `outDir: dist`, `include: ["src"]`. Compiled output goes to `dist/`
(`main: dist/index.js`, `start: node dist/index.js`). There is no `src/app.ts`/`src/server.ts`
split — `src/index.ts` builds the app, connects Mongoose, and listens.

## Response envelope (one shape)

One consistent shape across every controller, the health route, and the error handler:

```jsonc
// success — always HTTP 200 today
{ "data": <payload>, "message": "OK" }
// error
{ "data": null, "message": "<error message>" }
```

There is **no `success` flag**, **no `error.code`**, and **no `meta`**. There are also
**no `ok()`/`created()` response helpers** — controllers call
`res.status(200).json({ data, message: "OK" })` directly. New controllers must emit this
exact shape by hand, and tests must assert against it.

The error envelope is rendered in exactly one place: `src/middleware/errorHandler.ts`.

## Error model

- **`ApiError`** (`src/utils/ApiError.ts`) — `class ApiError extends Error` with a
  `status: number` field, constructed as `new ApiError(status, message)`. There are **no**
  named subclasses (`NotFoundError`, `ConflictError`, …).
- Two factory helpers exist and should be reused: `notFound(what)` → 404
  `"<what> not found"`, and `conflict(msg)` → 409.
- Services `throw` these; controllers never try/catch — `catchAsync` forwards the rejection.
- **`errorHandler`** maps `err instanceof ApiError` → `err.status`, everything else → 500,
  and responds `{ data: null, message: err.message || "Server error" }`. Error messages are
  **not** suppressed in production, and stack traces are not logged.
- Mongoose `CastError` / `ValidationError` / duplicate-key (11000) and Joi errors are
  **not** normalized anywhere — a bad ObjectId currently surfaces as a raw 500. (See Findings.)

## Validation flow

- **Joi 17**. `validateBody(schema)` (`src/middleware/validate.ts`) validates `req.body`
  with `{ abortEarly: false }`, throws `new ApiError(422, error.message)` on failure, and
  assigns the coerced `value` back onto `req.body`.
- **It only covers the body** — there is no params/query validation factory.
- Schemas are **not** yet colocated anywhere: no `*.schema.ts` file exists, and no route
  currently uses `validateBody`. When adding validation to a new module, write Joi schemas
  (e.g. `src/schemas/<name>.schema.ts` or alongside the routes) and wire them through the
  existing `validateBody` — **do not introduce Zod.**
- Types are hand-written; there is no schema→type inference (`z.infer` has no Joi analogue
  in use here).

## Auth primitives

- **`requireAuth`** (`src/middleware/auth.ts`) — reads `Authorization: Bearer <token>`,
  `jwt.verify(token, process.env.JWT_SECRET)`, assigns the payload to `(req as any).user`,
  and forwards `new ApiError(401, ...)` when the header is missing or the token is invalid.
- **`requireAdmin`** — checks `(req as any).user?.role !== "admin"` → `ApiError(403)`. Must
  run **after** `requireAuth`.
- **Bearer tokens in the `Authorization` header** — no cookies, no refresh-token flow.
- There is **no token-signing helper and no login/register endpoint**. `User`
  (`src/models/User.ts`) has `email`, `passwordHash` (`select: false`), `name`,
  `role: "user" | "admin"`, but nothing issues tokens or hashes passwords yet. An auth
  feature must add signing — reuse `jsonwebtoken`, matching `requireAuth`'s verification,
  and hash with the already-installed `bcryptjs`. **Do not introduce JOSE.**
- `req.user` is reached through `(req as any).user` — there is no `src/types/express.d.ts`
  augmentation.

## Environment config

**Raw `process.env`, read directly at each use site.** There is no validated/typed config
module and no `dotenv` call in the source — env vars are expected to be present in the
process (loaded externally, e.g. by `nodemon`/the shell).

Declared in `api/.env.example`:

| Var | Used in | Purpose |
| --- | --- | --- |
| `PORT` | `src/index.ts` | listen port (defaults to `4000`) |
| `MONGO_URL` | `src/index.ts` | Mongoose connection string |
| `JWT_SECRET` | `src/middleware/auth.ts` | token verification secret |
| `CORS_ORIGIN` | `src/index.ts` | allowed browser origin (the `web/` dev server) |

New vars are added to `.env.example` and read via `process.env` at the use site, matching
the current pattern. (Centralizing this is a Finding, not a rule.)

## Build & scripts

- `npm run dev` — `nodemon --exec ts-node src/index.ts`
- `npm run build` — `tsc -p .`
- `npm start` — `node dist/index.js`
- `npm test` — `jest`

There is no lint script, no ESLint config, no husky/lint-staged, and no `clean`/`rimraf`
step (`dist/` is not wiped between builds).

## Logging

`morgan("dev")` for HTTP access logs, mounted after `express.json()`. Application logging
is bare `console.log` (only `console.log("api up")` in `src/index.ts`). There is **no**
shared logger module and no per-request id/child logger. New code logs the same way
(`console.*`) unless the user opts into a logger.

## Naming

- Controllers/services/routes: dot-suffixed kebab/lowercase — `product.controller.ts`,
  `product.service.ts`, `product.routes.ts`.
- Models: **PascalCase singular filename** — `Product.ts`, `User.ts` — exporting a
  PascalCase model const (`export const Product = mongoose.model("Product", ...)`).
- Utils: camelCase filename matching the export (`catchAsync.ts`, `formatDate.ts`), except
  the error class file `ApiError.ts` (PascalCase, matches the class).
- `routes.ts` files **default-export** their `Router`; services, utils, middleware, and
  controllers use **named exports**.
- Controller handlers use short verb names (`list`, `getOne`) and are imported namespaced
  (`import * as controller from "..."`).

## Testing conventions

jest + supertest are installed but **nothing is configured or written**: no `jest.config.*`,
no `__tests__/`, no `*.test.ts`, no `ts-jest`/babel transform, and no in-memory Mongo. The
first test run will need a transform configured. `test-writer` should assert against the
`{ data, message }` envelope described above.

## Feature workflow

Work is planned **per module** and built **one slice at a time**:

1. `module-planner` writes `_docs/features/<module>/<module>-plan.md` plus ordered slice files
   (`01-<slice>.md`, `02-<slice>.md`, …) — the number is the build order. These live under
   `_docs/features/` at the **repo root**, not in this project folder, because a plan spans
   backend and frontend.
2. You review and edit those files.
3. `module-builder` executes **one slice**, then marks it `built`.
4. `test-writer` covers it from that slice's testing checklist; `code-review` checks it against
   this contract. Both on demand.

Only this file (`ARCHITECTURE.md`) and `MODULE_REGISTRY.md` live at this project's root —
`api/`, recorded in `.claude/workspace.json` at the repo root, which is how the skills locate
this project.

## Findings — observed issues (recorded, NOT fixed)

Onboarding is non-destructive; nothing below was changed. These are opt-in cleanups the user
can request later.

1. **Duplicate date helper.** `src/utils/formatDate.ts` (`formatDate`) and the private
   `toDayString` inside `src/services/report.service.ts` have identical bodies
   (`d.toISOString().slice(0, 10)`). **Assumed canonical: `utils/formatDate.ts`** (see
   Decisions). `report.service.ts` was left untouched.
2. **Routing bug — POST maps to the list handler.** `src/routes/product.routes.ts` has
   `router.post("/", requireAuth, requireAdmin, controller.list)`. The create path runs the
   *list* controller; there is no `create` controller or `createProduct` service.
3. **Validation middleware is dead code.** `validateBody` exists and works but **no route
   uses it**, and no Joi schema file exists anywhere. Every endpoint is currently unvalidated.
4. **No auth endpoints.** `User`, `requireAuth`, `requireAdmin`, and `bcryptjs` exist, but
   nothing signs a token or hashes a password — there is no login/register route or service.
   The `web/` client posts to `/auth/login`, which this API does not serve.
5. **`report.service.ts` is unreachable.** `dailyStockReport()` has no controller or route.
6. **DB/validation errors are not normalized.** A malformed `:id` produces a Mongoose
   `CastError` → generic 500 instead of 400. Duplicate-key (11000) on `Product.slug` /
   `User.email` → 500 instead of 409.
7. **Error messages leak in production.** `errorHandler` returns `err.message` verbatim for
   500s and never logs the error/stack.
8. **`strict: false`** in `tsconfig.json`, plus `(req as any).user` casts and untyped
   Mongoose models — no type safety on request user or documents.
9. **Raw `process.env` everywhere**, unvalidated. `mongoose.connect(process.env.MONGO_URL)`
   compiles only because `strict` is off (`string | undefined`). Missing env vars fail at
   runtime, not startup.
10. **Express 4 is in maintenance mode.** Staying on 4 is fine and is what this contract
    records (hence mandatory `catchAsync`); upgrading to 5 would remove the wrapper
    requirement — a deliberate, separate migration.
11. **No tests, no lint.** jest/supertest are installed with no config or specs; no ESLint.

## Decisions log

- Structure: **layered** (`controllers/`, `services/`, `routes/`, `models/`, `middleware/`,
  `utils/`) — recorded as-is, not migrated to domain-modules.
- **Express 4 + mandatory `catchAsync`** on every async handler.
- CommonJS, **no** `.js` import extensions, **no** path aliases.
- Response envelope: **`{ data, message }`** — no `success` flag, no response helpers.
- Errors: single `ApiError(status, message)` class + `notFound`/`conflict` factories.
- Validation: **Joi** via `validateBody` (body only).
- Auth: **jsonwebtoken** Bearer tokens, verified inline in `middleware/auth.ts`.
- Env: raw `process.env`, declared in `.env.example`.
- Logging: morgan + `console.*`.
- **Assumed default (user was not available to confirm):** `utils/formatDate.ts` is the
  canonical date helper; `report.service.ts`'s `toDayString` is the duplicate to retire
  later. Left in place.
- Project location: `api/`. Package manager: npm.
