## Findings (recommendations, not auto-fixed)

These are observations for the user to act on later — onboarding does not change any of them:

1. **`globals.css` is missing.** `components.json` points Tailwind's CSS entry at
   `src/app/globals.css`, but that file does not exist in the repo, and no `tailwind.config.js`
   exists either. Theming/tokens have not been set up yet — likely a job for a theming step
   (e.g. `font-theme-setup`) before real UI work begins.
2. **No `.env.example`.** `lib/env.ts` requires `BACKEND_URL` (server) but there's no example env
   file documenting it for new contributors.
3. **Auth is a stub.** `hooks/use-auth.ts` returns a hardcoded `null` user from local
   `useState` — there is no session/cookie/token reading, no `lib/auth/` module, and no
   `middleware.ts`/`proxy.ts` route protection. Treat auth as not-yet-built rather than assuming
   an existing strategy.
4. **`@hookform/resolvers` is on the v3 line while `zod` is v4.** Verify `zodResolver`
   compatibility before wiring the first real RHF+Zod form.
5. **No lockfile committed**, so the package manager (npm/pnpm/yarn/bun) can't be determined from
   the repo alone.
6. **`features/products/types.ts` and `schema.ts` aren't derived from each other** — `Product`
   (`{ id, name, price }`) is a hand-written interface, `productSchema`/`ProductInput`
   (`{ name, price }`) is a separate Zod schema with no `id`. Not a blocker, just worth aligning
   the next time this feature is touched.
7. **Only 2 shadcn primitives and 2 shared components exist** (`Button`/`Input`;
   `Heading`/`InputField`). The shared `overlay/`, `layout/`, and `data-display/` groupings from
   the toolkit's convention have no folders yet — create them on first use rather than
   pre-scaffolding empty folders.
