# Module Registry — acme-admin

The dedup ledger. **Check here FIRST** before creating any component, hook, util, type, or
service. If a suitable piece exists, import it — never recreate. Every frontend skill reads this;
the builder skills update it.

## Features (src/features/)

| Feature | Path | Owns | Public surface (index.ts) |
| --- | --- | --- | --- |
| products | features/products/ | `ProductCard`, `ProductList` (components); `useProducts` (hook, TanStack Query); `fetchProducts` (api fn); `Product` (type); `productSchema`/`ProductInput` (Zod schema, not currently re-exported from the barrel) | `ProductList`, `useProducts`, `Product` (type) |

Feature anatomy present for `products`: `types.ts`, `schema.ts`, `hooks/`, `api/`, `components/`,
`index.ts`. Not present: `constants/`, `template/` (the feature has no composed "screen" file —
`app/page.tsx` renders `ProductList` directly).

Notes for reuse:
- `fetchProducts()` (features/products/api/products.api.ts) — GET `/products` via the shared
  `api` axios instance, unwraps a `{ data: Product[] }` envelope. Follow this envelope-unwrap
  shape for new API fns against this backend.
- `useProducts()` (features/products/hooks/use-products.ts) — query key `["products"]`. Namespace
  any new products-related query keys under `"products"`.
- `productSchema`/`ProductInput` (features/products/schema.ts) validate `{ name, price }` only —
  narrower than the `Product` type (`{ id, name, price }`) in `types.ts`; the two are not derived
  from each other. New feature work should decide whether to align them, but onboarding leaves
  this as-is (non-destructive).

## Decisions log

- Stack: Next.js 15 App Router + TS strict + Tailwind v4 (globals.css not yet created) + shadcn/ui
  (Button, Input only) + axios (BFF-only) + Zod 4 + T3 Env + TanStack Query v5 + RHF 7 (declared).
- Paradigm: React function components + hooks; Client Components explicitly marked `"use client"`.
- Project location: `.` (repo root). Package manager: not determinable (no lockfile committed).
- Backend connection: BFF proxy (`app/api/[...path]/route.ts`). Token strategy: not yet
  implemented.
- Roles → routes: none defined yet.
- Forms: RHF + Zod intended via shared `*Field` only (`InputField` is the sole example so far).
  Typography: `cva` primitive (`Heading` only so far).
- Components: generic → `components/shared` (`form/`, `typography/` in use today); domain-specific
  → `features/<name>/components`. Env: T3 Env (`lib/env.ts`) only.
- Theming/fonts: not yet set up — `globals.css` referenced by `components.json` is missing from
  the repo.
